# Data Integrity Notice

`raw/student_employability.csv` is a **SYNTHETIC** dataset generated by
`src/generate_dataset.py`. It was created using a hand-designed scoring
formula plus random noise — it is **not** collected from real students or
real placement outcomes.

**Why synthetic:** the team did not have access to an anonymized real
survey/placement dataset at project start. Synthetic data lets us build
and demonstrate the full pipeline (EDA → preprocessing → modeling →
explainability → deployment) honestly, without presenting fabricated
outcomes as real-world evidence.

**Design choice baked into the generator:** fundamentals (ML/DL/SQL/Stats
scores), end-to-end + deployed projects, internship months, and
interview/communication scores are weighted much more heavily than
`hackathons_attended`. `hackathons_won` gets a small positive nudge. This
encodes the project's starting hypothesis into the ground truth so the
model has a genuine, non-trivial, non-deterministic relationship to
discover — noise is added so no single feature perfectly predicts the
outcome.

**What this means for your report / viva:**
- You CAN say: "In our synthetic dataset, the model found that internship
  experience and end-to-end/deployed projects were far stronger
  predictors of job-readiness than hackathon attendance."
- You CANNOT say: "This proves hackathons don't help real students get
  jobs." That would require real data.
- If you later obtain a real, anonymized dataset with the same column
  names, it can be dropped into `data/raw/` and the entire pipeline
  (`src/preprocessing.py`, `src/train.py`, `app/streamlit_app.py`) will
  work unchanged.
